# Review spacing: development protocol v1

Prepared 3 November 2026 (Malaysia), before any new controller evaluation. Status: engineering development only, not a main study or preregistration. No positive result or novelty is assumed. Historical code, protocols, raw outputs and adverse findings remain unchanged.

Question: Does spacing score-conditioned reviews preserve limited review opportunities and change downstream treatment-policy regret compared with consecutive reviews? The development comparisons pair each controller with M1 and M2-FULL separately; changing controller and monitoring signals simultaneously is not the primary contrast.

Four arms: M1-CONSEC, M1-SPACED, FULL-CONSEC, FULL-SPACED. Monitoring scores, their frozen thresholds, common initial T-learner and candidate/AIPW acceptance gate are inherited unchanged from ablation study run_20261102_012152. Same caps 2/4/8 and same two-issued-alert cap. All arms observe the same window data and raw monitoring scores. Model recommendations do not affect logged data.

CONSEC: first issued alert starts a review in that window and consecutive reviews until cap/end of horizon, exactly as before.
SPACED: first issued alert starts eligibility, with a review in that same window. After any performed review, skip the next window. A later review requires both (a) at least two window indices since the previous performed review and (b) the CURRENT raw monitoring score strictly exceeds that monitor's frozen threshold. If the score is low, do not review; eligibility remains for later windows. Accepted and rejected reviews both consume one unit and reset the spacing clock. Further issued alerts neither reset spacing nor replenish capacity. Review eligibility uses raw scores even after the issued-alert cap is reached, just as ongoing consecutive reviews do not require fresh issued alerts. There is no new detection rule, reference reset, threshold adjustment or future/change-point access.

Example: an initial alert at 5 gives CONSEC reviews 5/6 under cap 2; SPACED could review 5/7 if the score at 7 exceeds threshold. If score stays low, the second review remains unused. The spaced controller can spend at most six units in 12 windows, so a cap of 8 does not imply equal achievable or realized workload. Report actual reviews, unused capacity and timing; do not claim workload matching from equal caps. Spacing can delay helpful adaptation and harm results.

Engineering evaluation only: two seeds per scenario [360100,360102), 1,000 customers/window, five unchanged scenarios, 12 windows. Both seeds are developmental and permanently excluded from a later unseen main evaluation. Mocked unit tests use seed 360099. Reuse frozen calibration without retuning. Verify source hashes/software versions and initial-model report against the reference run; scan project CSV seed columns for collisions and stop if any exists. Do not retry an exposed run and count it as independent evidence.

Inherited shifts at window 7 and cost 10 are unchanged solely for development comparability. The controller must not read CHANGE or synthetic truth when deciding eligibility. Truth remains offline scoring only. A later inferential test must separately consider shift-onset variation and predeclare its settings before new results; no unseen main mode is supplied here.

Compare SPACED minus CONSEC regret for each monitoring signal, all scenarios and caps. Negative favors SPACED. Save pre/postchange regret, actual reviews/alerts/accepted updates, harm and complete logs. Two-seed descriptive bootstrap intervals are engineering output only, not research inference. Zero difference does not establish equivalence. No tuning on this development output will be called a confirmatory result.

Before running: tests pass; review and commit new files; run preflight; preserve output on interruption. Expected engineering runtime is a few minutes, not guaranteed. No changes are made to the accepted-update rule, which still applies a candidate only next window and has no sequential-safety guarantee.

Prior-art boundary: RCCDA (NeurIPS 2025, doi:10.52202/085713-5183), Sections 3-4, already studies resource-aware adaptive updates with a virtual queue. Our finite review-cap/causal policy-loss evaluation differs in formulation, but simple spacing is not established as new. Complete closest-work checks are still needed; CausalStream and OnlineCML full-text overlap remains unresolved. This extension does not itself establish M0-versus-causal superiority, explainability benefit or publication readiness.
