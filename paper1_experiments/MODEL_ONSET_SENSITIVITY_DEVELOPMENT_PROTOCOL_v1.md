# Initial-model and onset sensitivity: development protocol v1

Prepared 6 November 2026 before new extension outcomes. Engineering development only; no main/inferential mode. Extends PAPER1_DIRECTION_DECISION_20261106.md. Preserve all historical work and negative results.

Question: how do initial training realizations and shift timing affect the incremental policy value of monitoring signals under common update procedures? This is a sensitivity/replication-and-extension design, not a claim of new monitoring or guaranteed superiority.

Fixed factors: original generator magnitudes, cost 10, 12 windows; initial data/fitting seeds 42,1042,2042 (800/200 split random state 42 for each); onsets 4,7,10; five original scenarios. Each 1000-row initial dataset is generated by the historical mechanism with its specified seed. Varying initial seed varies training realization and forest randomness together. Initial datasets are not selected by model quality. Seed 42 intentionally reproduces the historical initial data/model.

Arms M0 (statistics 0–8), M1 (0–9), M2-FULL (0–12) and PERIODIC. Fixed calendars: cap 2=4/8; cap 4=3/6/9/12; cap 8=1/3/4/6/7/9/10/12. Alert cap 2; first alert starts consecutive reviews. Candidate/gate 70/30 split, strata age group x treatment, seed+period; baseline-nuisance AIPW lower pointwise mean−1.96SE>0 gate; apply next window. Each arm has its own incumbent. Shared candidate fitting is cached, not separate per-arm compute. No sequential-safety claim.

Treat-all, treat-none and frozen-model baselines are saved on every stream. Do not omit unfavorable baseline comparisons or choose a best fixed policy from evaluation truth and claim it deployable. M2-FULL combines subgroup and assignment-contrast additions; historical separate-signal ablations remain relevant.

Each initial fit receives its own stable centers/scales, thresholds and held-out null assessment. Statistics and finite-background live Shapley calculations are inherited from the frozen ablation source, but no Shapley statistic enters any arm's score. Expensive incumbent explanation audits are omitted from this sensitivity runner; explainability is not an endpoint. Retaining live summary computation maintains the frozen monitoring-vector definition. Record that joint runtime differs from historical XAI-heavy runs.

SMOKE: n=200; scale 3, calibration 5, held-out null 3 and evaluation 1 stream seed per scenario. DEVELOPMENT: n=1000; scale 10, calibration 40, held-out null 20 and evaluation 3 seeds per scenario. All three initial fits and onsets are retained. These counts are engineering allocations, not precise false-alert validation or research power. Independently audit and recalibrate a later main study.

SMOKE namespaces: scale [410010,410013), calibration [410100,410105), null [410200,410203), evaluation [410300,410301). DEVELOPMENT: scale [420010,420020), calibration [420100,420140), null [420200,420220), evaluation [420300,420303). Upper bounds excluded. Unit-test stream seed 409999 only. Initial data/fitting seeds are intentionally reused; evaluation/calibration seed sets are disjoint. Proposed stream ranges are not certified unused until preflight scans saved CSV seed columns and the user-visible source/history audit is reviewed. No claim about unrecorded/external runs.

Paired evaluation windows are reused across initial fits, arms, caps and onsets. make_window(seed,period,scenario,n,onset) uses the same random draws; only onset-triggered generator parameters differ. This is controlled pairing, not independent replication across those factors. Stable data do not change with onset: evaluate each stable stream once (onset marker 7), not three times. Smoke has 39 unique stream/initial-fit/scenario/onset configurations; development has 117 (nominal grids 45/135 include duplicate stable cells). Each configuration has 12 method-cap rows and 144 period rows. Development: 1404 run rows,16848 period rows,4212 benchmark period rows; smoke:468,5616,1404 respectively.

Endpoint: mean period-average oracle-relative policy loss across onset..12, with cumulative counterpart and entire period trajectories. Stable uses windows7..12 solely as common scoring horizon; stable detection is NA. Report within each initial fit/onset/scenario/cap; do not pool repeated views as independent observations. Later onset has a shorter horizon: mean-per-window loss does not remove finite-horizon adaptation opportunity differences. Also save pre-onset loss, reviews, alerts, accepted updates, harm and detection/misses/delay. Synthetic truth is offline scoring only.

Save all paired seed-level differences: FULL−M1, M1−M0, every alert arm−PERIODIC and every adaptive arm−each of the three benchmarks; all mean/cumulative posthorizon loss. No pilot p-values, equivalence claims or bootstrap research intervals. Development is exposed; later main seeds and initial-fit generalization must be specified separately. No main settings, power claims or runtime guarantee are supplied.

Provenance: require frozen ablation and original source hashes, unchanged historical schedule source; committed new script/protocol/tests; no dirty tracked files; exact normalized protocol hash. Development additionally checks versions against the completed ablation manifest. Smoke may use a different environment but cannot be pooled with Windows results. Scan project CSV seed and stream_seed columns, including untracked files; error on any proposed stream overlap or unreadable/malformed relevant seed data. Save source/protocol snapshots, config, seed manifest, versions, commit and per-phase timing before/main output. Unique output directories; checkpoint after each evaluation configuration. No auto-resume or fresh-evidence retry. Interrupted/exposed output is preserved.

Engineering gates: original setting reproduces historical generator/controller results on common fields; altered onset acts only at the specified window; stable streams computed once; model-specific calibration; no truth leak; all arms share window data; exact review dates/caps, gate and next-window application; baseline loss identities. Run full historical tests on the user machine. Measure smoke and development phase runtimes before estimating full-run costs. Outcomes do not determine which cells are retained.
